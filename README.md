## Результат работы predictions.py:

#### Прогноз вычисления:
 * **1)** 2 + 3 * 4 == 14
 *  **2)** (2 + 3) * 4 == 20
 * **3)** 17 // 5 == 3.4
 * **4)** 17 % 5 == 2
 * **5)** -7 // 2 == -3.5

#### Результат на Python:
  
 * **1)** 2 + 3 * 4 == 14
 * **2)** (2 + 3) * 4 == 20
 * **3)** 17 // 5 == 3
 * **4)** 17 % 5 == 2
 * **5)** -7 // 2 == -4

### Объяснения: 
 * Первое и второе вычисление сошлись т.к. Python следует математическим правилам порядка операций(операция * выше по приоритету чем + или -)
 * Во втором скобки дают выше приоритет чем *
 * В третьем и в пятом // это целоцисленное деление и оно округляет в меньшую сторону т.е. 3.4 -> 3 и -3.5 -> -4
 * В четвертом % это остаток от деления и он одинаков

### Разница между / и //

  *  `/` (Обычное деление) — выполняет классическое деление и всегда возвращает число с плавающей точкой (float), даже если числа делятся нацело.


     ** Пример: 4 / 2 выдаст 2.0.

  *  `//` (Целочисленное деление) — делит число и округляет результат вниз (в сторону минус бесконечности) до ближайшего целого. Возвращает целое число (int), если хотя бы один операнд был целым.


     ** Пример: 5 // 2 вернет 2 (а не 2.5).

        Важный нюанс с отрицательными числами: округление идет именно вниз (меньше по числовой прямой). Например, -5 // 2 вернет -3, потому что -3 меньше, чем -2.5`.

### Почему `range(a, b)` не всегда соответствует заданию №1

`range(a, b)` по умолчанию идёт только в сторону увеличения и **не включает `b`**.

Например:

`range(1, 5)` даёт `1, 2, 3, 4`, а по заданию нужно вывести `1, 2, 3, 4, 5`.

Кроме того, если `a > b`, например `a = 5`, `b = 1`, обычный `range(5, 1)` не выдаст числа в обратном порядке. Для этого нужен отрицательный шаг:

`range(5, 0, -1)`.

Поэтому для задания №1 удобнее использовать условие и цикл `while`, как в `range_numbers.py`: он позволяет явно задать оба направления и включить конечную границу.

### Почему цикл завершается

Если используется цикл вида `for i in range(1, 5)`, переменная `i` последовательно принимает значения `1, 2, 3, 4`. После этого значений в диапазоне больше нет, поэтому цикл заканчивается.

Если используется `while`, например `while i <= 4`, цикл завершается потому, что на каждой итерации `i` увеличивается на 1. После `i = 4` следующим станет `i = 5`, и условие `i <= 4` станет ложным.

### Объяснения:

* **`append()` и присваивание по индексу.** `items.append(value)` добавляет новый элемент в конец списка, а `items[i] = value` заменяет уже существующий элемент (при неверном индексе будет `IndexError`).
* **`sorted()` и `sort()`.** `sorted(items)` возвращает новый отсортированный список и не меняет исходный. `items.sort()` меняет сам список и возвращает `None`.
* **Копия списка.** Запись `copy = items` связывает два имени с одним списком, поэтому изменения видны через оба имени. Независимую копию создаёт `items.copy()`.
